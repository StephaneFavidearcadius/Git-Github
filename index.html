02

QU'EST-CE QUE GIT ?

Git est un système de contrôle de version.

Il permet de garder l'historique de ton projet et de savoir ce qui a changé, quand et pourquoi.

VERSION 01
VERSION 02
VERSION 03
VERSION 04
03

POURQUOI GIT ?

SANS GIT
projet-final.zip projet-final-2.zip projet-final-v2.zip projet-vraiment-final.zip projet-final-final-2.zip
AVEC GIT
commit — version 1 commit — version 2 commit — version 3 commit — version 4

Git évite le chaos des multiples copies. Chaque modification est tracée proprement.

04

GIT VS GITHUB

Git

Outil installé sur ton ordinateur. Il gère l'historique de ton code localement.

LOCAL

GitHub

Plateforme en ligne qui héberge des repositories Git et permet la collaboration.

REMOTE
TON ORDINATEUR → Git → REPOSITORY LOCAL → push → GITHUB

Git ≠ GitHub

05

1

2

Lancer l'installateur. Conserver les options recommandées.

3

Git Bash

06

VÉRIFIER L'INSTALLATION

git --version
RÉSULTAT git version 2.47.0

Que faire si la commande n'est pas reconnue ?

Git n'est pas installé ou n'a pas été ajouté au PATH. Relance l'installateur et vérifie les options.

07

CONFIGURER GIT

Git associe chaque commit à un nom et une adresse email.

git config --global user.name "Votre Nom"
git config --global user.email "votre@email.com"
git config --global --list

La commande --list permet de vérifier ta configuration.

08

CRÉER SON PREMIER PROJET

Git ne crée pas ton projet. Git vient gérer les versions de ton projet.

mon-premier-projet/
├── index.html
├── style.css
└── script.js

Crée un dossier, puis ajoute-y des fichiers. C'est ce dossier que Git va surveiller.

09

OÙ SUIS-JE ?

Le terminal travaille toujours dans un dossier précis. C'est fondamental.

pwd
RÉSULTAT ~/Desktop/mon-premier-projet
ls
RÉSULTAT index.html   style.css   script.js

Avant d'utiliser Git, vérifie toujours que tu es dans le dossier racine de ton projet.

10

INITIALISER GIT

git init

Cette commande transforme le dossier courant en repository Git local.

AVANT
mon-projet/
├── index.html
└── style.css
→
APRÈS
mon-projet/
├── .git/
├── index.html
└── style.css

Le dossier .git contient toutes les informations nécessaires à Git. Ne jamais le modifier manuellement.

11

GIT STATUS

git status

git status est l'une des commandes que tu utiliseras le plus.

Que montre git status ?

Il montre ce qui a changé, quels fichiers sont nouveaux, quels fichiers sont prêts à être commités, et sur quelle branche tu te trouves.

12

FICHIERS NON SUIVIS

GIT STATUS Untracked files:
  index.html
  style.css
  script.js

Git voit les fichiers mais ne les suit pas encore.

FICHIERS DU PROJET → GIT → NON SUIVIS
13

GIT ADD

git add .

Cette commande prépare les modifications pour le prochain commit.

WORKING DIRECTORY → git add → STAGING AREA

Le . signifie : tous les fichiers et modifications du dossier courant concernés par Git.

git add index.html

Ou ajouter un fichier spécifique en nommant le fichier à la place du point.

14

STAGING AREA

La staging area est une zone intermédiaire entre tes fichiers et l'historique Git.

WORKING
DIRECTORY
git add →
STAGING
AREA
git commit →
GIT
HISTORY

Tu choisis ce que tu veux inclure dans le prochain commit. C'est un filet de sécurité intentionnel.

15

GIT COMMIT

Un commit enregistre officiellement une version de ton projet dans l'historique Git.

git commit -m "Initial commit"
git commit → Créer une version
-m → Ajouter un message

Que signifie le -m dans git commit -m ?

16

L'HISTORIQUE

git log --oneline
a82f31d Update homepage
f92a21c Add navigation
b73c11a Initial commit

Chaque commit devient un point dans l'histoire du projet. Le plus récent apparaît en haut.

18

CONNECTER LE LOCAL À GITHUB

git remote add origin URL_DU_REPOSITORY
remote connexion vers un repository distant
origin nom conventionnel donné à cette connexion
URL adresse du repository GitHub
LOCAL REPOSITORY → origin → GITHUB REPOSITORY
19

VÉRIFIER LA CONNEXION

git remote -v
RÉSULTAT origin  https://github.com/... (fetch)
origin  https://github.com/... (push)
fetch récupérer les modifications distantes sans les fusionner
push envoyer tes commits vers le repository distant
20

PREMIER PUSH

git push -u origin main

push envoie les commits de ton repository local vers GitHub.

git push → envoyer
origin → repository GitHub
main → branche principale
-u → suivi entre branche locale et distante
21

GIT PULL

git pull récupère les modifications depuis le repository distant et les intègre dans ton projet local.

GITHUB → pull → TON ORDINATEUR
git pull

Utilise git pull quand : tu travailles sur plusieurs ordinateurs, tu travailles en équipe, ou des modifications ont été faites à distance.

25

GIT CLONE

git clone permet de récupérer un repository GitHub complet sur son ordinateur.

git clone https://github.com/user/projet.git
cd projet
GITHUB → clone → ORDINATEUR
26

LES BRANCHES

Une branche permet de travailler sur une version parallèle du projet sans modifier directement la branche principale.

main
feature
git switch -c feature
git switch main
